# 代理提示词

## 概述

代理名称为norain,分为两个端：服务端与客户端，以python为核心语言。具有win/Linux的双兼容性.支持**Hysteria2**和**Trojan**两套协议。要求可以自动部署并加入环境变量。

## 客户端

##### 概述

客户端分为9个功能模块，以sing-box为内核：

- **代理模块**：核心,负责转发。

- **分流模块**：负责分流流量。

- **监控模块**：通过监控固定网站，分析代理的问题，给出报告。

- **自维持模块**：维持代理正常运行，防止被杀死或沉默，代理死亡的第一时间迅速拉起。

- **阻断模块**：监控模块抛出某种异常且无法正常启动时时进行全域网络阻断。

- **修复模块**：负责重置代理为最初状态。

- **启动模块**：负责维持开机自启动，以及其他重启问题

- **内控制模块**：自适应选择链路/协议,并完成自动控制

- **外控制模块**：接入命令行,通过环境变量的norain下属指令进行控制,返回代理运行状态

##### 代理模块

代理模块是代理客户端的核心。代理模块通过访问文件：cfg.toml。读取下面数据：

- 代理服务器地址/端口

- 需要转发的流量

- 转发的协议

从而决定代理方式和目标。

这一步是最简单的。可以参考github相同代理实现，避免重复造轮子。

##### 分流模块

分流模块用于控制全局流量分流。

分流模块的目标是:优先本地dns解析，如果无法解析，将国外的流量访问定向到服务器,通过代理服务器向国外dns发出申请；国内流量访问定向到国内的dns。以通过dns解析检测。

基本逻辑是：

1. 接受到某个访问申请和目标地址

2. 查询白名单和黑名单，如果是白名单内的，直接分流到国外；如果是黑名单的，直接分流到国内。白名单的恒用服务器代理解析dns,黑名单使用国内的代理解析dns,如果都没有，进入下一步

3. 访问本地DNS服务器，并且判断是国内还是国外。
   
   A.如果查询到是国内，用国内分流检测是否正常访问，如果可以：国内分流访问。如果不行：用国外分流检测是否正常访问，如果可以：改其判断为国外并且加入白名单，以。 ‘ 国外分流访问；如果不行：去公共dns解析，并更新解析结果；
   
   B.如果查询到是国外，用国外分流检测是否正常访问，如果可以：国外分流访问。如果不行：向服务器发起dns解析，通过服务器更新的解析结果并更新本地dns；
   
   C.都不行：进入下一步

4. 查询目前还在正常维护 **GeoIP数据库** 去判断是国内还是国外，如果是国内，直接在国内dns解析，如果是国外，向服务器发出请求，收到解析结果。根据判断结果完成分流。并且更新dns和访问，如果没有查询到，直接向服务器发出请求，收到解析结果。

考虑两个特殊情况：服务器问题/本地连接问题

服务器问题：dns连接不上/网站本身正在维护

本地连接问题：本地互联网未连接；

##### 监控模块

监控模块是检测代理是否运行正常的模块，监控方向主要是IP检测/连通性检测/dns解析位置。要求低消耗高频率的监控代理运行状态。

监控模块比较可能碰上下面几种情况：

全网络连通性失败：未连接互联网：返回错误码：100

部分网站连通性正常，大部分网站连通性失败(无法检测IP)：阻断模块启动，返回错误码：301

国内连通性测试正常/国外连通性测试失败/，pv4/ipv6检测：走代理是无返回，走直连是返回国位置：这一般是服务器链路失效，服务器未启动/连接失败，返回错误码：600

国内连通性测试正常/国外连通性测试正常，ipv4/ipv6检测：走代理是ipv4是国内位置，ipv6是国外位置，走直连是返回国位置：这一般是服务器/客户端ipv4链路配置问题，返回错误码：604

国内连通性测试正常/国外连通性测试正常，ipv4/ipv6检测：走代理是ipv6是国内位置，ipv4是国外位置，走直连是返回国位置：这一般是服务器/客户端ipv6链路配置问题，返回错误码：606

国内连通性测试正常/国外连通性测试正常，ipv4/ipv6检测：走代理是国内位置，走直连是返回国位置：这一般是检测链路/分流配置问题，返回错误码：400

监控模块还可以监控dns解析位置，当dns对国外访问解析定位在的国内时,返回错误码:401

##### 自维持模块

自维持模块维持代理的重要补充,其目标是其他模块被杀死/异常时迅速拉起/重启,自身要有保活能力(可以考虑和代理/分流模块互拉),同时在出现无法重启修复的问题时启动阻断.

基本功能是:

监视所有模块在线情况;

当其他模块出现掉线情况时,自动拉起相应模块;

在监视模块抛出错误码时,杀死相应进程并且调用修复模块尝试修复,并且重启代理;

修复失败时启动阻断模块.

自维持模块需要不断扫描,同时尽可能降低性能使用.

要考虑和其他模块的协同工作,以免和其他模块出现冲突:例如:自维持模块发起修复的过程中,监控模块继续抛出错误码,导致无法修复.其他问题请自己分析.

##### 阻断模块

阻断模块是为了防止在代理中断的情况下因切换直连而被定位真实国内ip.

当自维持模块无法成功维持代理时,会启动阻断模块.阻断模块会操作防火墙,只留下有限的网络连接,这些网络将会再蓝名单给出.,阻断其他所有网络连接(注意绕过监控模块),

阻断模块启动后进入阻断模式,需要给出弹窗提醒用户,并且给出可能问题推测(以方便用户修复)同时杀死其他所有模块.

阻断模式下可以利用命令行手动关闭阻断状态,恢复正常防火墙放行,进入非阻断模式(这不一定代表代理修复完成,此时代理不一定启动)

当启动启动模块时,阻断模块自d动恢复为非阻断模式.

##### 修复模块

修复模块通过对损坏模块的运行文件进行修复,同时可以修复初始状态的计算机本身配置(包括代理端口,网络配置等)

修复模块有四种修复:

- 文件修复:扫描目录+判断哈希是否文件损坏/缺少,通过重新解压安装包的一些代码修复.

- 内置配置修复:修复代理内置配置,复位代理内部.

- 完全配置修复:修复所有配置(包括用户的配置),恢复计算机的配置(比如阻断模块对防火墙的更改)

- 重载修复:完全卸载代理并清除相应的痕迹(注册表,计算机设置,所有文件)重新安装.

注:重载修复模块里面的卸载部分应当被打包为一个独立指令.

子维持模块的修复只用文件修复和内置配置修复,四种分别打包为指令.

##### 启动模块

启动模块负责开机自启动,以及启动其他模块.

启动模块在运行时,会先进入测试检测模式

在测试检测模式时,启动模块会检查阻断模块模式,如果配置被更改就先调节阻断模块为非阻断模式,之后拉起分流模块,代理模块,监控模块,当监控模块并且通过后会激活代理模块的互拉保活,启动自维持模块

启动模块可以用指令运行.也可以通过安全模式非开机自启动.

##### 内控制模块

内控制模块负责协调各个模块运行,同时控制各个模块运行参数

包括但不限于:

对代理模块的协议选择(通过测速/连通性决定)

对分流模块的自更新

在启动测试检测模式时暂时抑制自维持模块拉起

,所有多模块交互操作和启动/杀死模块需要内控制模块审批.

##### 外控制模块

外控制模块就是命令行模块,norain下分为三大类:

- 配置类:配置白名单/黑名单/蓝名单/监控测试名单,配置协议为自适应/Hysteria2/Trojan,配置启动正常模式/安全模式/配置代理服务器/dns服务器等所有需要配置的东西

- 控制类:杀死/重启/启动模块,修复模块,卸载代理,以某种方式一次性启动使用某个模块的某个功能

- 调试类:加上-t参数可以看每个模块的运行情况和返回结果.

### 服务端

##### 概述

服务端名称为 norain-server，是 norain 的服务端部分，以 Python 为控制层、sing-box 为数据面内核，兼容 Windows/Linux，支持 **Hysteria2** 和 **Trojan** 两套协议，支持单用户自用场景。要求可以自动部署、开机自启，并自动加入环境变量。

- **入站模块**：核心，负责监听、认证和转发。
- **配置模块**：负责读取 `server.toml` 并生成 sing-box 配置。
- **证书模块**：负责证书生成、检查、加载。
- **守护模块**：负责维持 sing-box 正常运行，异常时拉起。
- **防火墙模块**：负责放行或关闭协议端口。
- **状态日志模块**：负责状态查询、日志记录和轮转。
- **外控制模块**：接入命令行与环境变量，提供 `norain-server` 指令。
- **部署更新模块**：负责安装、更新、卸载和自启动注册。

服务端不做多用户、配额、流量统计、复杂分流、阻断模式、客户端式修复体系。原则是：一个配置文件、一个 sing-box 进程、一个守护、一个 CLI。

##### 入站模块

入站模块是服务端的核心。它通过读取配置文件 `server.toml`，决定监听哪些协议、端口、密码和证书。

基本逻辑是：

1. 读取 `server.toml`。
2. 如果启用 Hysteria2，生成 Hysteria2 入站，监听 UDP 端口，使用单用户密码认证。
3. 如果启用 Trojan，生成 Trojan 入站，监听 TCP 端口，使用单用户密码认证。
4. 两套协议可以同时启用，也可以只启用其中一套。
5. 认证通过后统一交给 `direct` 出站，服务端不做分流。
6. Trojan 可选配置 fallback，指向本地静态 HTTP 服务；不配置 fallback 时允许直接拒绝，不强制伪装。
7. 入站配置变更后，必须通过配置模块重新生成，并由守护模块重启 sing-box。

要求：

- Hysteria2 默认监听 `443/udp`。
- Trojan 默认监听 `443/tcp` 或独立端口，避免与 Hysteria2 冲突。
- 密码不得硬编码，必须从配置或环境变量读取。
- 不实现多用户数组，只保留一个用户。
- 不实现服务端侧分流规则，`route.final` 固定为 `direct`。

##### 配置模块

配置模块负责把用户可读的 `server.toml` 转换成 sing-box 可用的 `sing-box.json`。

基本逻辑是：

1. 读取 `server.toml`。
2. 校验必填项：协议是否至少启用一个、端口是否合法、密码是否为空、证书路径是否存在。
3. 根据启用的协议生成对应入站。
4. 生成 `direct` 出站。
5. 生成日志配置。
6. 写入 `sing-box.json`。
7. 调用 `sing-box check` 校验配置。
8. 校验失败时不得覆盖原配置，输出明确错误。

要求：

- 配置生成必须幂等，重复执行结果一致。
- 修改配置后不自动重启，由外控制模块或守护模块决定是否重启。
- 支持 `norain-server config show` 查看当前配置。
- 支持 `norain-server config edit` 编辑 `server.toml`。

##### 证书模块

证书模块负责 TLS 证书的生成、检查和加载。

基本逻辑是：

1. 支持三种模式：`acme`、`manual`、`self-signed`。
2. `acme` 模式优先使用 sing-box 内置 ACME；没有域名时不允许使用该模式。
3. `manual` 模式读取用户指定的证书和私钥路径。
4. `self-signed` 模式用 openssl 生成自签证书，供个人自用。
5. 每次生成配置前检查证书文件是否存在、证书与私钥是否匹配、是否过期。
6. 证书无效时阻止配置写入，并返回明确错误。

要求：

- 证书路径必须来自配置或环境变量。
- 自签模式必须在配置中显式开启。
- 证书更新后通过 `norain-server reload` 重新加载，不直接重启系统服务。
- 提供 `norain-server cert check` 和 `norain-server cert self-signed --domain <域名>`。

##### 守护模块

守护模块负责维持 sing-box 正常运行，是服务端的自维持模块。

基本逻辑是：

1. `norain-server run` 启动后先检查配置和证书。
2. 启动 sing-box 子进程。
3. 每隔固定时间检查：进程是否存活、端口是否监听、最近日志是否有 fatal。
4. 进程退出时记录日志并尝试重启。
5. 连续重启失败达到上限后停止重启，保留日志并返回错误。
6. Linux 使用 systemd `Restart=on-failure`；Windows 使用服务或计划任务作为外层保活。
7. Python 守护只负责拉起 sing-box，不负责拉起其他模块。

状态码建议：

- `0`：正常。
- `110`：配置文件缺失或格式错误。
- `120`：证书无效。
- `130`：端口被占用。
- `140`：sing-box 进程退出。
- `150`：sing-box 二进制缺失。
- `160`：连续重启失败。

要求：

- 检查间隔默认 30 秒，可配置。
- 最大连续重启次数默认 3 次。
- 不实现客户端式阻断模块。
- 守护模块不得与用户手动 `stop` 冲突；手动停止后不自动拉起。

##### 防火墙模块

防火墙模块负责放行服务端协议端口。

基本逻辑是：

1. 根据启用的协议确定需要放行的端口。
2. Hysteria2 放行 UDP 端口。
3. Trojan 放行 TCP 端口。
4. Linux 优先使用 `ufw` 或 `firewalld`；没有则提示手动放行。
5. Windows 使用 `netsh advfirewall firewall add rule`。
6. 卸载或关闭协议时移除对应规则。

要求：

- 只放行配置中启用的端口。
- 不开放无关端口。
- 提供 `norain-server firewall open`、`norain-server firewall close`、`norain-server firewall status`。
- 防火墙操作失败时必须输出具体原因，不得静默忽略。

##### 状态日志模块

状态日志模块负责查询服务端运行状态和记录日志。

基本逻辑是：

1. `norain-server status` 输出 JSON，包含服务状态、sing-box 进程状态、启用协议、端口、证书状态、重启次数、最近错误。
2. `norain-server log` 查看日志。
3. `norain-server log -f` 持续跟踪日志。
4. 日志文件超过大小上限时轮转，保留有限份数。

##### 外控制模块

外控制模块就是服务端命令行模块，通过 `norain-server` 指令和环境变量控制服务端。

配置类：

环境变量：

```bash
NORAIN_SERVER_HOME=/etc/norain-server
NORAIN_SERVER_CONFIG=/etc/norain-server/server.toml
NORAIN_SERVER_LOG=/var/log/norain-server
NORAIN_SERVER_SINGBOX=/usr/local/bin/sing-box
```

要求：

- 启动时优先读环境变量，其次读默认路径。
- 所有指令必须返回明确退出码。
- `fix` 只做配置重建、证书检查、缺失文件恢复，不实现客户端四类修复。
- `uninstall` 默认保留日志，`--purge` 才删除日志和配置。

##### 部署更新模块

部署更新模块负责从零安装、更新和卸载服务端。

Linux 基本逻辑：

1. 识别架构，下载或复制对应 sing-box。
2. 校验哈希。
3. 安装到 `/usr/local/bin/sing-box`。
4. 创建 `/etc/norain-server/` 和 `/var/lib/norain-server/`。
5. 生成默认 `server.toml` 和 `sing-box.json`。
6. 注册 systemd 服务。
7. 写入 `/etc/profile.d/norain-server.sh`，导出环境变量。
8. 执行配置校验和启动测试，失败回滚。

Windows 基本逻辑：

1. 下载或复制 `sing-box.exe` 到 `%ProgramFiles%\norain-server\`。
2. 校验哈希。
3. 配置目录使用 `%ProgramData%\norain-server\`。
4. 注册服务或计划任务实现开机自启。
5. 用 `setx` 写入 `NORAIN_SERVER_HOME` 和 `NORAIN_SERVER_CONFIG`。
6. 执行配置校验和启动测试，失败回滚。

要求：

- 部署脚本必须幂等。
- 重复安装不得覆盖已有用户配置，除非显式 `--force`。
- 更新前备份配置和证书。
- 卸载时清理自启动项、环境变量、二进制和安装目录。
- 必须支持 `NORAIN_HY2_PORT`、`NORAIN_TROJAN_PORT`、`NORAIN_DOMAIN`、`NORAIN_CERT_MODE`、`NORAIN_PASSWORD` 等环境变量注入。
- 部署完成后输出服务端摘要，不输出密码明文。
