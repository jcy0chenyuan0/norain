# 0010 监控目标、阈值与误报处理

- 状态：已接受（2026-11-14，按最初目标修订，见文末）
- 日期：2026-11-14
- 关联：原稿「监控模块」业务码 100/301/400/401/600/604/606

## 背景

原稿定义了业务码，但没有定义监控目标、预期结果和判定规则。

## 建议

**探测记录字段**：目标、路径（`direct`/`proxy`）、IP 版本、解析结果、耗时、协议、结果、错误原因。

**目标分组**（`monitor_targets`，每项要有 `group`、`url` 或 `host:port`、`expect`）：

| 组 | 路径 | 用途 | 草案 |
|---|---|---|---|
| `local_net` | 直连 | 判断本地是否联网 | 至少 2 个互不相关的目标，例如本地网关和一个公共 DNS 的 TCP 53 端口 |
| `proxy_v4` | 代理，IPv4 | 代理 IPv4 链路 | 1 个 204 响应端点 |
| `proxy_v6` | 代理，IPv6 | 代理 IPv6 链路 | 1 个 IPv6 端点；用户没有 IPv6 时整组禁用 |
| `primary` | 按分流 | 用户关心的主要目标 | 用户自己配置 |

**判定规则**（每组独立计数；连续失败 `failure_threshold = 3` 次判故障，连续成功 `recovery_threshold = 2` 次判恢复）：

| 业务码 | 判定 |
|---|---|
| 100 | `local_net` 全部目标故障 |
| 600 | `local_net` 正常，`proxy_v4` 和 `proxy_v6` 都故障（`proxy_v6` 禁用时只看 `proxy_v4`） |
| 604 | `local_net` 正常，只有 `proxy_v4` 故障 |
| 606 | `local_net` 正常，只有 `proxy_v6` 故障 |
| 301 | `local_net` 和代理正常，但 `primary` 中超过一半故障 |
| 400 | 分流或检测链路本身异常：rule-set 不可用、探测器自身出错、规则与预期路径不符 |
| 401 | 诊断：应走代理的域名被本地 DNS 解析（ADR 0006） |

**误报处理**：

- 业务码有优先级：100 > 600 > 604/606 > 400/401 > 301，同时只上报优先级最高的那一个。
- 修复期间同一业务码不重复告警。
- 状态变化（进入或退出故障）才发事件，持续状态不重复发。

## 与最初目标的差异（待修订）

最初目标对业务码的定义依赖「走代理和走直连时查到的出口 IP 位置」：

- 400：国内外连通都正常，但走代理查到的出口仍是国内位置。
- 604 / 606：走代理时 IPv4（或 IPv6）出口是国内位置，另一个 IP 版本是国外位置。
- 600：国内连通正常、国外失败，走代理查询出口无返回。
- 301：大部分网站连通失败，并触发阻断。

上面的判定表没有使用出口位置，v0.5 开始前要按最初目标重写：增加一个「出口 IP 查询」探测，分别经代理和直连、分别用 IPv4 和 IPv6 执行。

1. 目标分组方式和判定表。
2. 监控结果是否需要通知（系统通知或 webhook），还是只写入日志和 `status`？

## 修订

2026-11-14，用户：**以最初目标（docs/reference/original-goals.md）为准，除非有硬性 bug。**

业务码的判定以最初目标为准，即「与最初目标的差异」一节列出的定义：依据国内/国外连通性，以及分别走代理和直连、分别用 IPv4 和 IPv6 查询到的出口 IP 位置。301 触发阻断。上文的判定表作废，v0.5 实现时按最初目标重写；阈值和去抖动（连续失败 3 次、连续成功 2 次）保留，用来避免网络抖动误触发阻断。
